# CB Trainers — платформа учёта проектной активности тренеров

Веб-приложение для сбора, ведения и аналитики данных о проектной активности тренеров: кто в каких проектах участвует, в каких ролях, какие задачи выполняет и с какой периодичностью. Тренеры сами вносят свои записи, а администратор видит сводную статистику, матрицы распределения и аналитические дашборды.

## Архитектура и структура проекта

```
src/

├── App.vue                     # Корневой компонент
├── router/
│   └── index.ts                # Маршруты + navigation guard (проверка авторизации/ролей)
├── shared/                     # Supabase-клиент, типы и общие компоненты
├── entities/                   # Модели и API активностей, проектов, тренеров и справочников
├── features/                   # Редакторы активностей, проектов и тренеров
├── pages/                      # Точки входа страниц по FSD
├── widgets/                    # Общий layout приложения
└── views/
    ├── HomeView.vue            # Стартовый роут — восстановление сессии и редирект по роли
    ├── LoginView.vue           # Экран входа
    ├── TrainerDashboard.vue    # Рабочий стол тренера (список задач/проектов + CRUD)
    ├── AdminDashboard.vue      # Аналитический дашборд с графиками ECharts
    ├── AdminTableView.vue      # Сводная матрица "тренеры × роли"
    ├── DictionariesView.vue    # Проекты, тренеры и управление словарями
    ├── ProjectEditView.vue     # Карточка проекта
    └── TrainerEditView.vue     # Карточка тренера

### Ключевые архитектурные решения

- **FSD-границы.** Маршруты подключают `pages`, пользовательские сценарии находятся в `features`, а модели и CRUD — в `entities`.
- **Единая точка API.** Страницы и UI-компоненты не обращаются к Supabase напрямую. CRUD тренеров, проектов, активностей и справочников находится в соответствующих `entities/*/api`.
- **Единый редактор активности.** Таблица тренера, календарь и Gantt используют одну форму из `features/activity-editor`.
- **Типизированная база.** Контракт Supabase описан в `shared/api/supabase/database.types.ts`, а воспроизводимая схема — в `supabase/migrations`.
- **Единый layout.** Все защищённые страницы обёрнуты в `DashboardLayout`, который показывает меню в зависимости от роли пользователя.
- **Реактивная аналитика.** Все графики на дашборде — это `computed`-свойства, которые пересчитываются из «сырых» данных, загруженных одним пакетом запросов.

Подробные правила расширения и карта CRUD: [`docs/architecture.md`](docs/architecture.md).

## Модель данных

Приложение работает со следующими таблицами Supabase:

| Таблица | Назначение | Основные поля |
|---------|-----------|---------------|
| `trainers` | Тренеры (пользователи) | `id`, `full_name`, `city_id`, `division_id` |
| `roles` | Роли в проектах | `id`, `name`, `weight` |
| `project_types` | Типы проектов | `id`, `name`, `weight` |
| `project_names` | Проекты и модули | `id`, `name`, `audit_index`, `status_code`, `project_type_id`, `parent_project_id`, `participant_count` |
| `project_statuses` | Статусы проектов | `code`, `name`, `sort_order`, `is_active`, `is_terminal` |
| `project_delivery_formats` | Форматы проведения для ЦА и ГУ | `code`, `name`, `sort_order`, `is_active` |
| `annual_budget_items` | Строки бюджета года | `id`, `name`, `is_active` |
| `directions` | Направления проектов | `id`, `name`, `description`, `is_active` |
| `project_direction_links` | Связи проектов с направлениями | `project_id`, `direction_id` |
| `project_materials` | Материалы проектов | `project_id`, `type_code`, `status_code`, `title`, `location` |
| `production_calendar_days` | Праздничные дни и рабочие субботы для нормирования | `event_date`, `day_type`, `name` |
| `cities`, `divisions` | Справочники профиля тренера | `id`, `name`, `is_active` |
| `trainer_certifications` | Допуски тренеров к проектам | `trainer_id`, `project_id`, `status_code`, `valid_from`, `valid_until` |
| `activity_types` | Типы активностей | `id`, `name`, `description`, `weight`, `is_active` |
| `delivery_formats` | Форматы выполнения | `id`, `name`, `description`, `weight`, `is_active` |
| `recurrence_types` | Периодичность выполнения | `id`, `name`, `description`, `weight`, `is_active` |
| `trainer_projects` | **Основная таблица записей**: связывает тренера с проектом, ролью и классификацией задачи | см. ниже |

### Таблица `trainer_projects`

Каждая строка — одна запись об активности тренера:

- `trainer_id` — ссылка на тренера
- `project_type_id` — тип проекта *(обязательно)*
- `project_main_id` — основной проект *(обязательно)*
- `project_sub` — подпроект / тема (свободный текст)
- `role_id` — роль тренера в проекте *(обязательно)*
- `activity_type_id` — тип активности
- `delivery_format_id` — формат выполнения
- `recurrence_type_id` — периодичность
- `task_desc` — описание задачи (свободный текст)
- `comments` — комментарии
- `is_duplicate` — метка «шаблон» (см. функцию дублирования)

Поле `weight` в справочниках задумано как коэффициент нагрузки для расчёта взвешенного индекса загрузки тренера. Поле `is_active` определяет, показывается ли значение справочника тренерам в форме.

## Аутентификация и роли

Вход по **логину и паролю** через Supabase Auth (без почтового сервиса). Сессия хранится в Supabase client (JWT + refresh token). Слой API: `src/entities/auth`, стор: `src/stores/auth.ts`.

- **Администратор** — логин `admin`, пароль задаётся при деплое (по умолчанию `adminpass`, см. миграцию). Роль `admin` в `app_metadata` JWT.
- **Тренер** — логин и пароль создаёт администратор в карточке тренера. Роль `trainer`, `trainer_id` в `app_metadata`.

Маршруты защищены `navigation guard` в `router/index.ts`:

- Страницы с `meta.requiresAuth` недоступны без профиля → редирект на `/login`.
- Авторизованный пользователь, зашедший на `/login`, перенаправляется на главную.
- Маршруты с `meta.role` предназначены для соответствующей роли (`admin` / `trainer`).

Доступ к данным в PostgreSQL защищён **Row Level Security** (см. миграции `202608240001`, `202608240002`). Настройка Supabase Dashboard: [`docs/supabase-auth-setup.md`](docs/supabase-auth-setup.md).

## Логика работы для пользователей

При открытии приложения `HomeView` пытается восстановить сессию из `localStorage` и перенаправляет пользователя на его рабочую область в зависимости от роли.

### Тренер

Роль тренера — вести собственный список проектной активности.

1. **Вход.** Тренер вводит логин и пароль на экране входа.
2. **Мои задачи** (`/trainer/dashboard`). Отображается таблица всех записей тренера с колонками: тип проекта, проект, подпроект, роль, тип активности, формат, периодичность, описание.
3. **Добавление записи.** Кнопка «Добавить запись» открывает форму. Обязательные поля — **Тип проекта**, **Основной проект**, **Роль**. Остальные (тип активности, формат, периодичность, описание, комментарии) — опциональны. Списки выбора подгружаются из справочников, причём показываются только активные значения (`is_active = true`).
4. **Редактирование / удаление.** Каждую запись можно отредактировать или удалить (с подтверждением).
5. **Дублирование записи (шаблон).** Кнопка «Дублировать» создаёт копию записи с меткой `is_duplicate = true` — она помечается тегом «Шаблон». Идея: быстро размножить похожие задачи, а затем отредактировать копии. При сохранении изменений метка шаблона снимается.

### Администратор

Роль администратора — контроль, аналитика и ведение справочников, проектов и тренеров.

#### 1. Аналитический дашборд (`/admin/dashboard`)

Визуализация распределения ресурсов и ролей на базе ECharts. Сверху — быстрые метрики (всего тренеров, выполнено задач, активных ролей). Ниже — сетка изменяемых по размеру панелей с графиками:

- **Доли ролей в проектах** — круговая диаграмма.
- **Рейтинг по ролям в проектах** — накопительная гистограмма по тренерам.
- **Охват уникальных тренеров по ролям** — сколько тренеров задействовано в каждой роли.
- **Топ проектов по количеству задач** — горизонтальная гистограмма.
- **Проекты × Типы проектов** — тепловая карта.
- **Матрица: Тренер × Проект** — тепловая карта.

#### 2. Сводная таблица (`/admin/table`)

Матрица «тренеры × роли»: для каждого тренера показано количество задач в каждой роли и итоговая сумма. Роли отсортированы в заданном приоритетном порядке (лидирование проекта → основной методолог → курирование → участник рабочей группы → тренер/ведущий). Показываются только тренеры хотя бы с одной задачей.

**Клик по строке** тренера открывает его рабочий стол в режиме администратора (`/admin/trainers/:id`) — там администратор может просматривать, добавлять и редактировать записи **от имени тренера**.

#### 3. Проекты и тренеры

Разделы `/admin/projects` и `/admin/trainers` содержат отдельные списки и полнофункциональные карточки. В проектах доступны поиск, фильтрация по статусам, структура модульной программы, материалы и параметры проведения. В карточке тренера ведутся профиль и проектные допуски.

Раздел `/admin/work-norms` содержит редактируемый производственный календарь. Его праздничные дни и рабочие субботы действуют для всех тренеров и подсвечиваются в календаре и Gantt.

#### 4. Управление словарями (`/admin/dictionaries`)

Табличный редактор всех справочников: тренеры, роли, типы проектов, проекты, типы активностей, форматы выполнения, периодичность. Для каждого справочника доступны добавление, редактирование и удаление. В зависимости от типа справочника в форме появляются дополнительные поля:

- **Вес** — коэффициент нагрузки (для роли/типов/проектов и др.).
- **Описание** — для активностей, форматов и периодичности.
- **Активен** — переключатель видимости значения тренерам в форме ввода.

## Запуск проекта

Требуется Node.js (рекомендуется LTS) и проект Supabase.

```bash
# установка зависимостей
npm install

# режим разработки (http://localhost:5173)
npm run dev

# архитектурная проверка, type-check и продакшен-сборка
npm run check

# локальный предпросмотр собранной версии
npm run preview
```

Скрипт `check` проверяет границы архитектуры, выполняет проверку типов через `vue-tsc` и собирает бандл Vite.

## Технические особенности

- **Тема оформления (light / dark / auto).** Стор `theme.ts` хранит выбор в `localStorage`, переключается по кругу кнопкой в шапке и отслеживает системную тему через `prefers-color-scheme`. Тёмная тема применяется добавлением класса `dark` к корню документа (совместимо с Tailwind).
- **Гибкие таблицы.** Таблицы Naive UI (`n-data-table`) с сортировкой, изменяемыми по ширине колонками, горизонтальным скроллом и «прилипающими» колонками действий.
- **Оптимизированная загрузка данных.** Справочники и записи грузятся параллельными пакетами через `Promise.all`, что сокращает время инициализации экранов.
- **JOIN-запросы Supabase.** Рабочий стол тренера подтягивает связанные названия из справочников одним запросом с вложенным `select` (например, `project_types (name)`).
- **Ленивая загрузка маршрутов.** Все view-компоненты подключаются через динамический `import()`, что уменьшает начальный бандл.
- **Переиспользование маршрута.** Компонент `TrainerDashboard` обслуживает и режим тренера, и режим просмотра администратором (по `props.id` из URL), переключая заголовки и поведение через `computed`.
```
